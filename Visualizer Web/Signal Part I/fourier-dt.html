01 ความถี่ใน discrete-time วนซ้ำทุก 2π — ต่างจาก continuous-time ตรงนี้ที่เดียว

ใน DT เรามีค่าเฉพาะที่ n เป็นจำนวนเต็ม ทำให้ ej(ω+2π)n = ejωnej2πn = ejωn — คนละ ω แต่ได้ลำดับเดียวกันเป๊ะ ผลคือสเปกตรัมทุกตัวในฝั่ง DT เป็นคาบ 2π และ “ความถี่สูงสุด” ที่มีความหมายคือ ω = π (สลับเครื่องหมายทุกจุด)

สองข้อที่ต้องติดหัวไว้

ej(ω + 2π)n = ejωn X(ej(ω+2π)) = X(ejω)

ความถี่ต่ำ = ω ใกล้ 0, ±2π, ±4π… · ความถี่สูง = ω ใกล้ ±π, ±3π… (สไลด์ 134)

02 DTFS — สัญญาณคาบ N จุด ใช้ฮาร์มอนิกแค่ N ตัว

ต่างจาก CT ที่ต้องใช้ฮาร์มอนิกอนันต์ ฝั่ง DT ฮาร์มอนิกตัวที่ k กับ k + N เป็นตัวเดียวกัน (จากข้อ 01) ผลรวมจึงจบแค่ N พจน์ และ ak เองก็เป็นคาบ N ด้วย

คู่สูตร DTFS

x[n] = Σk=<N> ak ejk(2π/N)n ak = 1N Σn=<N> x[n] e−jk(2π/N)n
Nคาบของสัญญาณ (จำนวนจุดต่อหนึ่งคาบ)
ω₀= 2π/N — ระยะห่างระหว่างฮาร์มอนิก
<N>บวก N จุดติดกัน ช่วงไหนก็ได้
ak+N= ak เสมอ — สัมประสิทธิ์เป็นคาบ
สูตรปิดของพัลส์คาบ: ak = sin(2πk(N₁+½)/N) / (N sin(πk/N)) และ a₀ = (2N₁+1)/N

03 DTFT — สัญญาณไม่เป็นคาบ: จาก N → ∞

เอาสัญญาณความยาวจำกัดมาทำให้เป็นคาบด้วยคาบ N แล้วปล่อย N → ∞ ระยะห่างฮาร์มอนิก ω₀ = 2π/N จะเล็กลงจนเส้นสเปกตรัมกลายเป็นเส้นโค้งต่อเนื่อง — นั่นคือ X(ejω) (สไลด์ 125–128)

คู่สูตร DTFT (4.14 / 4.15)

X(ejω) = Σ∞n=−∞ x[n] e−jωn x[n] = 12π ∫2π X(ejω) ejωn dω
Σฝั่งวิเคราะห์เป็นผลรวม (เวลาเป็นจุด ๆ)
∫2πฝั่งสังเคราะห์เป็นอินทิกรัลช่วงเดียวยาว 2π (ความถี่ต่อเนื่องแต่เป็นคาบ)
ωหน่วย rad/sample — ไม่ใช่ rad/s
Σ|x[n]|ต้องลู่เข้า สูตรถึงจะใช้ได้ (สไลด์ 129)

อ่านกราฟให้เป็น: ถ้าขนาดพุ่งสูงตรง ω = 0 (และ ±2π) แปลว่าสัญญาณนั้น “ช้า/เรียบ” = lowpass · ถ้าพุ่งตรง ω = ±π แปลว่าสลับขึ้นลงทุกจุด = highpass — ลองลาก a ไปทางลบดู

04 DFT — สุ่ม DTFT ให้เหลือ N จุด เพื่อให้คอมพิวเตอร์คำนวณได้

คอมพิวเตอร์เก็บ ω ต่อเนื่องไม่ได้ เลยสุ่ม X(ejω) ที่ ωk = 2πk/N จำนวน N จุดเท่ากับความยาวสัญญาณ — DFT คือตัวอย่างของ DTFT ไม่ใช่สูตรใหม่ลอย ๆ (สมการ 4.29)

คู่สูตร DFT (4.19 / 4.20)

X[k] = ΣN−1n=0 x[n] e−j(2π/N)nk x[n] = 1N ΣN−1k=0 X[k] ej(2π/N)nk
WN= e−j2π/N — twiddle factor, เขียนเป็นเมทริกซ์ X = Wx ได้
kช่องความถี่ที่ ωk = 2πk/N
X[k] = N akความสัมพันธ์กับ DTFS (4.28)
X[k+N]= X[k] — เป็นคาบ N
ใส่ตัวเลขคั่นด้วยจุลภาค (2–16 จุด)
kωkX[k]|X[k]|∠X[k]

เช็กกับสไลด์ 160: x[n] = {1, 2, 0, −1} ได้ X[k] = {2, 1−3j, 0, 1+3j} — สังเกต X[3] = X[1]* เพราะ x[n] เป็นจำนวนจริง

05 คูณในความถี่ = convolution แบบวน — กับดักที่ต้องระวัง

ใน DFT การคูณ Y[k] = X[k]H[k] ให้ผลเป็น circular convolution (ตัวที่เลยขอบจะวนกลับมาต้นแถว) ไม่ใช่ linear convolution แบบใน Lecture 02 — ดูตารางเทียบด้านล่าง

Exercise 3.3.1 — สองวิธี ผลลัพธ์เดียวกัน

y[n] = ΣN−1m=0 h[m] x[(n − m) mod N] ⟺ Y[k] = X[k] · H[k]
nlinearส่วนที่เลยขอบ (n ≥ N)circular

ค่าเริ่มต้นตรงกับสไลด์: x = {1,2,0,−1}, h = {1,3,−1,−2} → linear = {1,5,5,−5,−7,1,2} พอพับส่วนที่เกิน (n = 4,5,6) กลับไปบวกที่ n = 0,1,2 จะได้ circular = {−6, 6, 7, −5} · ถ้าอยากให้ DFT ให้ผลเท่ากับ linear ต้องเติมศูนย์ (zero-pad) ให้ยาวอย่างน้อย Nx + Nh − 1

06 FFT — ทำไมถึงเร็วขึ้นมหาศาล

DFT ตรง ๆ ใช้การคูณ N² ครั้ง FFT แบ่งลำดับเป็นคู่/คี่ซ้ำไปเรื่อย ๆ (decimation in time) จนเหลือ DFT ขนาด 2 จุด ทำให้เหลือ N log₂N

แนวคิดแบ่งครึ่ง (4.39–4.40)

X[k] = Σn คู่ x[n]WNnk + Σn คี่ x[n]WNnk = G[k] + WNk H[k] X[k + N/2] = G[k] − WNk H[k]

สองบรรทัดนี้คือ “ปีกผีเสื้อ” (butterfly): คำนวณ G[k] กับ H[k] ครั้งเดียว ใช้ได้ทั้งช่อง k และ k + N/2

ตัวอย่างจริง: เสียง 1 วินาทีที่ 44,100 Hz ถ้าใช้ DFT ตรง ๆ ≈ 2 พันล้านการคูณ แต่ FFT ≈ 6.8 แสน
